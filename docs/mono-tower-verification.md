`npm run test:browser` 在 DPR 1/2/3 下各运行 137 项原物件 GPU 检查与 153 项网站物件检查。检查覆盖球体遮挡后方线条、三扇图标门正反面的球体完全遮挡与部分遮挡、门前球体遮挡图案及圆周显示、出口球体显示、四种方向的门名平面与间距、网页标题字体、完整单词原生排版、相同字号与 kerning、单份名称、正反阅读方向、击鼓传字仅显示图标、三种门内 symbol 的可见性与投影线宽、透明出口图案、涟漪的方块表面范围与结束状态，以及真实键盘移动、镜头旋转、跳跃、安全鼠标寻路、自动进入门、手机手势、输入释放、形态切换、浏览器选择保存、操作图示和阅读页左上站点名称。

门名、按键和网页入口标题共用系统无衬线字体，门名字重默认为 500，按键与入口标题字重为 400。门名显示为 `Notes` 与 `Essays`。浏览器原生 Canvas 2D 以完整单词排版，字体自身的 kerning 处理相邻字母，`letterSpacing` 保持默认值 `0px`，两个名称使用相同字号、大写字母高度为 14 世界单位。文字底部与门框保持 12 世界单位间距。名称只有一个 mesh，观察背面时沿门平面水平转向。

门内 symbol 共用独立的 1.5 世界单位线条材质。Notes 使用几何笔记页，Essays 使用一段连贯笔迹，表达随笔书写。图案按最长边缩放至 38 世界单位，Essays 的实际几何尺寸为 38 × 8.0398 世界单位，中心位于门内高度 36 世界单位处。四种镜头方向测得图案笔画宽度，DPR 1 为 1.4911 至 1.5062 像素，DPR 2 为 2.9976 至 3.0084 像素，DPR 3 为 4.4929 至 4.5059 像素。击鼓 symbol 使用 `chuan-zi/public/favicon.svg` 的完整 SVG 副本，由 `SVGLoader` 读取笔画中心线并参与场景绘制。两个 SVG 文件逐字相同；原图三条竖线横坐标为 7、12、17，门内几何为 -9.5、0、9.5，四种镜头方向的两个投影间距均相等。

桌面 1280 × 800 与手机 390 × 844 的浏览器检查使用 `Range` 测量站点名称文字区域，列表页、notes 和 essays 的 x、y、width、height 均一致。

操作提示在最前图层显示，GPU 像素检查确认空白区域的 alpha 为 0、物件黑色内部的 alpha 为 255。桌面使用五组游戏物件动画，鼠标与 WASD 相邻，WASD 演示使用当前选择的控制模式；桌面与手机提示按键、手机操作按钮使用 1 像素直角边框，Tab 仅显示文字并与其他按键保持相同高度。手机使用四组动画：单指点击、双指缩放与平移、旋转和跳跃。单指点击与涟漪同时变化，双指间距与物件缩放同步，双指移动与物件平移同步。

`tests/tutorial-harness.ts` 通过公开的 `ControlTutorial.update()` 驱动真实物理与 WebGL，桌面每种尺寸通过 785 项检查，手机每种尺寸通过 655 项检查。检查覆盖按键高亮、三种 Tab 模式、所有图像随时间变化、独立手指的缩放和平移动画、手指外框与内部线条的 1 像素宽度、透明空间与不透明表面、每帧图形在各自画布区域内、循环结束淡出和元素释放。1280 × 800、390 × 844、320 × 568、844 × 390 均分别运行桌面与触屏模式，全部通过。

`npm run test:view` 通过真实 Chrome 多点触控检查手机初始放大倍数 1.5、缩放下限 1 与上限 3、双指平移到屏幕各个边缘、四次完整旋转及 320 × 568、844 × 390、390 × 844 尺寸变化。球体投影范围包含轮廓，保持水平 24 像素、顶部 76 像素与底部 88 像素间距。桌面提示距离底部 64 像素（1280 × 800）。三种控制模式经 Tab 选择后逐一刷新，均恢复上次选择；WASD 演示中球体实际运动方向也与所选模式一致。形态切换按钮背景为不透明黑色，界面层级高于提示。手机列表实际滚动后，顶部栏截图逐像素保持一致，正文不会透过顶部栏。浏览器修改 `--door-title-font-weight` 后，两份门名纹理即时更新为指定字重。

真实 Chrome 多点触控检查确认单指安全地面寻路、缩放和平移后继续点击寻路、双指手势结束保持位置、操作按钮尺寸与位置保持不变、跳跃按钮与两指手势同时操作、触摸取消释放和旋转按钮操作。触摸按住截图逐像素检查 RGB 通道相等，按钮持续使用黑白反馈；浏览器触摸高亮透明。手机显示三个操作按钮，单指拖动与双指手势不会触发寻路。手机列表入口名称保持一行，站点名称显示为 `Crisply2404`。

`npm test` 的 10 项物理和导航检查覆盖连续走廊的直接路线、环绕缺口的最短安全路线及其真实物理执行、经过真实轨迹检查的跳跃连接、平台接触距离恢复与点击目标到达。类型检查及生产构建通过。Godot 参考图验证原游戏物件；网站场景使用 ADR 0004 的入口与提示规则。

`npm run test:history` 构建生产网站，并启动独立预览服务器。真实 Chrome 分别启用与关闭返回缓存，通过鼠标寻路进入 Notes、后退、进入 Essays、前进与后退循环、再次进入 Notes、切换列表与游戏形态并进入 Essays。缓存模式检查实际的 `pageshow.persisted` 值，各次返回只保留一个可操作的场景，后退之后直接寻路进入其他门。

`npm run test:door` 在真实 Chrome 中分别使用桌面键盘、鼠标与手机触控进入三个入口，检查触发入口的当帧速度归零。进门前持续按住移动键，以及触发后持续按住移动、跳跃、重试、旋转、Tab，继续点击与使用手机按钮，球体均保持触发位置；每次进入仅触发一个目标。现有完整浏览器检查验证进入前的操作仍然可用，返回缓存检查验证后退后的各个入口继续可用。
