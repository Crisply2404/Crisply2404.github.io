# 网页保留 MONO TOWER 的物件与绘制规则

日期：2026-10-10

状态：已确定

## 要求

主页一比一移植原游戏物件及其细节。地图采用直走廊，入口连接个人网站内容；暂停界面无需移植。

## 决定

Three.js 中的 `VisualBuilder` 和 shader 使用原游戏的几何尺寸、方块邻接规则、屏幕空间线条、24 段圆帽、覆盖量量化、圆形球体深度和深度纹理遮挡。线宽为 2.5 世界单位，每个方向通过投影计算相同的屏幕宽度，并随窗口尺寸与 DPR 正确缩放。

物件包含标准平台、尖刺、球体、未完成门、完成门、双面编号、双面出口图案、接触标记及检查点。检查点保留旗帜朝向、激活填充、脉冲和整面旗帜遮挡。门牌文字使用从 Godot 导出的 glyph 图集、advance、kerning、offset、UV 与 baseline；透明文字不写入深度。

操作使用原游戏的物理参数、60 Hz 更新、跳跃缓冲、离开平台后的短暂跳跃窗口、提前释放跳跃、三种 WASD 方向、移动过程中的方向保持、90 度镜头旋转和原游戏触控图标。网页增加安全导航图与鼠标路径操作。

## 验证

`tests/fixtures/mono-tower/` 保存 Godot 4.7.2 实际渲染的参考 PNG。物件比较要求相对像素误差小于 2%，亮度比例在 98% 至 102% 之间，图形覆盖区域交集比例超过 98%；三种方向预览的相对像素误差小于 2%。这些阈值允许记录 Godot 与 WebGL 的实际光栅化差异。

浏览器直接读取 GPU 像素检查四种镜头方向、桌面与手机比例、DPR 1/2/3、重复线条亮度、球体遮挡及检查点遮挡。操作检查使用真实键盘、鼠标和多点触控事件。
